# L1 手机号码归属地批量查询

**批量手机号归属地查询工具** —— 一次粘贴，几秒查完 10 万个号码的归属地（省 / 市）、运营商和空号状态，支持按任意列筛选、导出 Excel。

纯离线单文件 HTML，**双击即用，不联网、不上传、不需要安装任何东西**。

> 手机号码归属地查询 · 批量号码筛选 · 空号查询 · 号码导出 Excel · 离线单文件

## 功能

### 输入：随手粘贴，自动清理

不用整理格式。整段微信聊天记录、Excel 表格、文档、网页都能直接粘进来：

```
张三 13800138000
李四：139 1234 5678
电话: +86-136-0000-1111
（139）1234-5678
１３８００１３８０００
```

自动过滤空格、横线、括号、全角字符、零宽字符、`+86` / `86` / `0086` 前缀，只留下真正的 11 位手机号。重复号码自动去重。

### 查询：归属地 + 运营商 + 空号

- **归属地**：精确到地级市，覆盖 31 省 355 市
- **运营商**：中国移动 / 联通 / 电信 / 广电，并标注虚拟运营商、物联网卡、上网卡、卫星电话
- **是否空号**：号段不存在即为空号（判定依据见下方说明）

### 筛选：四个维度随便筛

表格的**号码、归属地、运营商、是否空号**四个列头都可以点开筛选：

- 号码 → 按号段（`138`、`170`…），也可以直接搜完整号码或号码片段（输 `7908` 能找出 `17861379085`）
- 归属地 → 省 → 市，两级展开
- 运营商 → 运营商 + 号码类型
- 是否空号 → 是 / 否

多个条件可以叠加。

### 输出：复制 / 导出 Excel

- 勾选号码，一键复制到剪贴板（每行一个）
- 导出真正的 `.xlsx` 文件（不是假 Excel 的 csv），手机号存为文本格式，不会变成 `1.38E+10`
- 导出的内容 = 你当前看到的内容（筛选后 + 勾选的）

## 常见问题

**Q：手机号归属地可以离线查询吗？**

可以。号段与归属地的对应关系是公开信息（工信部号段分配 + 运营商公开数据），完全可以内置到本地。本项目把这个数据库压到 257 KB 塞进了 HTML，所以不需要任何网络请求。

**Q：能查空号吗？准确率多少？**

分两层：

- **号段不存在** → 判定为空号，这个 **100% 准确**，因为这种号码根本不会被分配给任何人
- **号段存在，但机主已销号/停机** → **查不到**。这个状态只存在运营商的 HLR 里，实时变化，不对个人开放，必须付费调用接口

所以「否」只代表号段已分配，不代表机主现在在网。想查真实在网状态，需要接运营商或第三方接口（市价约 0.003 元/条）。

**Q：数据会上传到服务器吗？**

不会。整个页面零网络请求，断网也能用。你可以用浏览器开发者工具的 Network 面板验证——打开页面后一条请求都没有。

**Q：最多能处理多少条？**

30 万条。这个量对应约 200 MB 内存，再往上普通电脑会吃不消。日常几万条毫无压力。

**Q：为什么不做成网站或 App？**

单文件 HTML 有三个好处：不用部署、不用登录、数据不出本机。对企业名单来说，第三点往往最重要——把几万条客户号码上传到别人的服务器，本身就是一个合规风险。

**Q：号码数据准吗？**

号段库共 **497,191 条号段**，覆盖 31 省 355 市，包含 192 / 195 / 196 / 197 等新号段。构建时做过全量交叉校验，逐条比对零差异。但号段会被运营商调整，如果你的号码很新，可能存在少量未收录的情况。

**Q：支持虚拟运营商和物联网卡识别吗？**

支持。按工信部号段批文标注：

- 虚拟运营商：`162` `165` `167` `170` `171`
- 上网卡：`145` `147` `149`
- 物联网专用：`146` `148` `172`
- 卫星电话：`1349` `1740x` `1749`

做电话外呼时，这几类号码接通率低或根本没人接，建议优先排除。

## 技术实现

几个有意思的点，给想看代码的人：

**号段库压缩到 257 KB**

497,191 条号段 → 行程编码（RLE）+ varint → 540 KB 二进制 → raw deflate → 197 KB → base64 263 KB。

浏览器端没用 `DecompressionStream`（需要 Chrome 103+，微信内置内核有风险），而是内置了一个约 90 行的 inflate 实现，纯 ES5，解压 540 KB 只要 30 ms。

**虚拟滚动**

DOM 结构是 `容器 > 占位层(撑开总高度) > 列表层(absolute + translateY)`，只渲染可视区上下各 8 行。所以节点数恒定在 319 个，与数据量无关。

**号码提取不用正则**

早期版本用正则直接匹配，结果遇到 `12580138000 12012345678` 会跨空格拼出一个假号码 `13800012012`。

现在改成：先按强分隔符（逗号、换行、括号、全角标点等）切片段，再对长度不足 11 位的相邻片段做贪心合并。既能认出 `139 1234 5678`，又不会跨号码边界误拼。

**性能瓶颈不在算法**

实测 10 万条：提取 105 ms + 去重 12 ms + 查表 12 ms = 129 ms。

剩下 1.9 秒全花在布局上——左侧文本框装着 1.1 MB 文字，重排一次就要 800 ms。所以把进度栏高度锁死、文字单行省略，避免它撑高面板导致文本框反复重排。
